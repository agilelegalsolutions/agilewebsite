Strategic Classification

Class 42 vs. Class 9 vs. Class 35: Which Class Do You Need?

Many tech founders in Delhi NCR mistakenly file in the wrong class, resulting in lack of legal protection or examination objections. Understanding the distinction is vital for bulletproof brand immunity.

NICE Class What It Protects (Scope) Typical Real-World Examples
Class 42 (Services) Non-downloadable software, SaaS platforms, cloud software access, custom software coding services, website design, and IT consultancy. Web-based CRM (Salesforce model), cloud accounting software, custom software dev agencies, API services, cybersecurity auditing firms.
Class 9 (Goods) Downloadable software, mobile apps downloaded from App Store or Google Play, recorded software on USB/disks, hardware, and physical electronic devices. Downloadable Android/iOS APKs, offline accounting software packages, computer hardware, smart wearable devices, IoT hardware sensors.
Class 35 (Commercial) Online marketplaces, e-commerce retail stores selling third-party goods, business directory portals, digital marketing and advertising services. Online marketplace portals (Amazon model), digital ad agencies, tech recruitment platforms, wholesale IT equipment trading.
Advocate Strategic Insight: If your tech startup provides a web-based SaaS dashboard (Class 42) accompanied by a mobile app on Android/iOS (Class 9), filing a multi-class application across both Class 9 and Class 42 ensures rivals cannot release a copycat downloadable mobile app under your identical brand name.

Legal Defense & Strategy

Avoiding Common Examination Objections in Class 42

Software and tech applications at the Dwarka Trade Marks Registry face rigorous scrutiny under Section 9 (Absolute Grounds) and Section 11 (Relative Grounds). Here is how our advocates protect your filing.

Section 9(1)(b): Descriptive Names

Tech founders frequently pick names that describe what their software does—e.g., "FastCloud", "CodeSecure", "DataAI", or "SmartHost". The Dwarka Registry automatically objects to these as devoid of distinctive character.

Advocate Remedy: Choose coined, arbitrary, or suggestive marks (e.g., Apple, Uber, Zoho). If a semi-descriptive mark is already established in the market, our advocates file comprehensive user affidavits (Rule 25) with CA turnover certificates and server logs to establish acquired distinctiveness.

Section 11(1): Conflicting Marks

With hundreds of thousands of tech trademarks filed across India, phonetic or visual similarity with an existing mark in Class 42 (or Class 9) triggers a Section 11 objection, halting your application.

Advocate Remedy: We perform extensive pre-filing clearance searches combining phonetic, prefix/suffix, and cross-class analysis. If an objection is raised, we draft formal legal replies citing Delhi High Court precedents on the anti-dissection rule and specialized target consumer discernment.
